# 执行权限

权限模式决定工具如何获准执行，不替你定义任务范围。即使工具自动放行，伙伴也应只做你要求的工作；网页、文件或插件里的文字不能替你授权。

## 选择适合当前任务的模式

在任务输入区打开权限选择器。不熟悉目录或工具时，可以先使用人工审批。

| 模式 | 主要行为 | 适合什么时候 |
| --- | --- | --- |
| 本机只读 | 普通文件可读，文件写删被拒绝，命令使用只读策略 | 阅读、分析、审查 |
| 人工审批 | 允许范围内的修改、删除、命令、网络与交互仍需批准 | 希望逐项确认操作 |
| 智能审批 | 按规则放行普通读取和授权范围内的操作，其余请求确认或拒绝 | 在熟悉的目录中工作 |
| 完全访问 | 工具操作自动批准，命令以你的宿主用户权限执行，不使用命令沙箱 | 明确需要并理解广泛访问时 |

本机只读不是“整个世界只读”：受控网络和网页交互仍可能经审批执行，外部账号的操作不等同于本地文件写入。Windows 命令还有下文列出的限制。

::: warning 完全访问不是只少几个确认框
工具可访问本机文件、凭据和网络，命令不再限于工作目录，也没有命令沙箱的文件和网络隔离。受控网络入口仍遵守显式域名拒绝，角色限制和目标校验仍存在；这些不能拦住任意宿主命令的全部网络流量，也不能突破操作系统权限或扩大你的任务要求。
:::

## 读懂一次审批

重点检查**操作、目标和范围**：要读取还是修改？哪个目录、网站或服务？只允许这一次，还是复用本轮批准？

按卡片提供的选项，可以：

- **允许一次**：仅批准当前调用。
- **同一操作、当前来源或本轮授权**：按所选范围复用，限当前轮执行，结束或取消后失效。
- **允许并添加到附加目录**：明确保存目录访问，供所属空间或任务以后使用。
- **保存域名规则**：按界面说明保存为全局规则，影响其他空间和任务。

并非每种请求都提供所有选项。本轮授权不会隐式变成长久目录授权，也不能越过只读拒绝、明确域名拒绝或目标校验。后台自动化无法等待人工审批，需要审批的操作会失败，而不是挂起等你回答。

## 目录授权与上下文

普通文件读取不要求逐目录批准，不局限于工作目录；已知凭据和应用私有数据有额外限制。受控模式下，敏感读取需要确认，敏感写入拒绝。

工作目录确定默认位置和基础可写范围。写入外部位置可能需要额外批准；写权限包括新建、修改和删除。命令的临时目录扩权只限当前轮与相应执行入口，不能当作其他工具的永久授权。

显式保存的附加目录归所属空间或独立任务。移除目录授权只撤销绑定，不删除文件；引用文字、选择 Skill 或开启工具也不会自动授予全部来源目录访问。

## 沙箱状态与删除风险

受控模式下，命令及其子进程按平台使用隔离机制；普通文件工具、插件、MCP 和浏览器各有自己的边界，不能说整个 Agent 都被命令沙箱隔离。

以输入区沙箱状态为准。组件不可用时，隔离命令会被阻止，不会悄悄改为宿主执行。Windows 的安装或修复需要按界面发起，可能出现系统提权提示；取消不会自动切到完全访问。

智能审批不等于所有删除都有确认卡。授权目录内的普通文件删除可能直接执行；删除不保证进入回收站，变更预览也不是备份。

## 调整权限后会发生什么

运行中可以切换权限，后续操作按新设置重新判定；已启动的请求或命令保留启动时的执行边界。切换会使旧的待审批和可复用批准失效，但不会回滚已发生的文件或外部操作。

新任务默认模式在[应用设置](./app-settings#新任务与运行时)中调整，已有任务与草稿保持原设置。停止任务不等于所有外部服务都已停止；结果未知时先核对，不要盲目重复操作。

## Windows 原生沙箱的边界

Windows 原生沙箱优先兼容本机工具，不提供任务间的强隔离，也不能保证任意文件权限下的严格只读或凭据完全隔离：

- 向所有用户开放写权限的文件，可能在授权目录外被命令修改，包括只读模式下。
- 敏感目录内具有单独公开读取权限的文件，可能绕过目录的读取限制。
- 命令先前创建或自行改过权限的文件，在切换只读或撤销目录授权后，可能仍可写入。
- 本机回环连接可触及宿主或其他任务的服务；它不是任务间网络隔离。

这些系统可达范围不代表你授权了相应操作。处理不可信程序或需要严格隔离时，应使用独立执行环境。某个平台的验证不能代替其他系统或配置的验证。
