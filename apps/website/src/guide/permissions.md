# 执行权限

任务有时只需要读取资料，有时需要修改文件、运行命令或访问外部服务。权限模式让你选择哪些操作可以继续，哪些需要先确认。

## 选择适合当前任务的模式

在任务输入区打开权限选择器。第一次处理不熟悉的目录或工具时，可以先使用人工审批，看清每一步操作。

| 模式 | 主要行为 | 适合什么时候 |
| --- | --- | --- |
| 本机只读 | 读取文件，拒绝文件工具写入，命令使用只读策略 | 阅读、分析、审查现有材料 |
| 人工审批 | 修改、命令和外部交互需要批准 | 希望逐项确认操作 |
| 智能审批 | 按规则放行安全查询和授权范围内的操作，其他操作请求确认 | 在熟悉的目录中持续工作 |
| 完全访问 | 命令使用你的本机权限执行，部分工具仍可能需要确认 | 明确了解任务所需的广泛权限时 |

不同平台支持的命令隔离能力可能不同，以输入区显示的沙盒状态和审批说明为准。「本机只读」限制的是本机文件修改，不能把它理解为外部账号也绝不会发生写操作。

::: warning 完全访问的含义
完全访问下，命令可能访问本机文件、凭据和网络。它不是“只少弹几个确认框”，也不能保证任意命令始终被限制在工作目录内。
:::

## 读懂一次审批

出现授权卡片时，重点检查三件事：

1. **要做什么**：是读取、修改、执行命令，还是请求外部服务？
2. **作用在哪里**：目标文件、目录、命令参数或服务地址是否符合预期？
3. **授权到什么程度**：只完成当前操作，还是涉及额外目录或更大的范围？

例如你只要求整理「旅行计划」目录，却看到操作要修改其他项目，先拒绝或停止，并告诉伙伴限定范围。拒绝后可以补充更明确的要求，让它采用其他可行做法。

## 目录授权与上下文

工作目录确定任务默认的文件位置和可写范围。普通文件读取不需要逐目录授权；写入其他位置时，按界面提示追加授权。策略会限制已知凭据和应用私有数据的访问；Windows 的执行边界见下文。

引用文字并不等于授予其来源目录的全部访问权；伙伴的工具选择、Skill 说明也不会绕过任务的权限上限。

## 调整权限后会发生什么

可以根据下一步工作调整权限，例如先只读分析，再允许写入整理后的文件。已经发生的文件修改或外部操作不会因为降低权限、停止任务而自动撤销。

如果希望新任务使用固定的默认模式，可以在「设置 → 运行时」调整。先在少量任务中确认行为，再更改默认值。

## Windows 原生沙箱的边界

Windows 原生沙箱优先兼容本机工具，不提供任务间的强隔离，也不能保证任意文件权限下的严格只读或凭据完全隔离：

- 向所有用户开放写权限的文件，可能在授权目录外被命令修改，包括只读模式下。
- 敏感目录内具有单独公开读取权限的文件，可能绕过目录的读取限制。
- 命令先前创建或自行改过权限的文件，在切换只读或撤销目录授权后，可能仍可写入。

这些系统权限不代表你授权了相应操作。处理不可信程序或需要严格隔离的任务时，应使用独立的执行环境。
