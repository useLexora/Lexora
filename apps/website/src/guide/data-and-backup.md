# 数据与备份

Lexora 开源自己的代码，不替你“开源”你的代码。任务与配置保存在本机；使用在线模型或外部工具时，调用所需内容会发送给对应服务。

## 哪些内容保存在本机

| 内容 | 存放或发送方式 |
| --- | --- |
| 任务、对话、伙伴与应用设置 | 当前 Lexora 数据目录 |
| 托管工作文件 | Lexora 数据目录内 |
| 自选外部工作目录 | 原磁盘位置，加入空间不等于整体上传 |
| API Key 与登录凭据 | 通过专门凭据入口，使用操作系统加密能力在本机保存 |
| 插件包、配置与私有文件 | 应用管理的插件数据；获准引用的外部文件仍在原位置 |
| 插件托管的模型与引擎 | 本机独立的推理资源区域；不等于普通插件文件备份 |
| 外部模型服务 | 由该服务自行管理文件与数据 |
| 在线模型、独立识图、语音和 OCR | 请求所需的文字、图片或音频发送到所选服务 |
| MCP、网页与插件外部调用 | 调用所需数据发送给相应服务；远程提取见[网页指南](./web-browsing) |
| 云备份 | 配置并启用后写入你指定的 WebDAV 或 S3 存储 |

模型上下文可能包含对话、引用和工具读取的文件片段。“本地优先”不代表所有操作离线，也不表示所有内容只会交给当前聊天模型。

::: info 配置不都是加密凭据
专门的 API Key 保存入口与普通配置不同。自定义请求头、任务内容或插件文件可能包含你自己填写的秘密；不要因为没有勾选“包含密钥”，就把备份视为可公开文件。
:::

## 查看数据目录与占用

打开「设置 → 数据存储」，查看当前目录、打开文件夹并按分类检查占用。

统计不包含所有外部目录。清理前区分工作文件、推理资源、缓存、日志与备份；不要直接删除正在使用的数据库、插件资源或模型文件。

## 创建一份本地备份

1. 点击「创建备份」，选择任务与空间、托管工作文件、伙伴、模型服务、连接、Skills、插件、自动化或应用设置等内容。
2. 如需包含密钥，开启对应选项并设置至少 8 位的备份口令。
3. 等待完成，点击「查看备份」，确认新的记录与所选范围。

### 备份包含什么

| 选择或资源 | 范围 |
| --- | --- |
| 任务与空间 | 相关记录与任务托管资料；托管工作文件另有选择 |
| 托管工作文件 | 应用管理的工作目录，不是整个外部项目 |
| 插件 | 安装包、配置、状态及受支持的插件自有文件 |
| 本地模型权重与引擎 | **托管推理资源不在上述插件备份内**，需要另行保留或重新准备 |
| 插件引用的外部文件、外部模型服务、外部工作目录 | 不随引用自动纳入备份 |

备份是按选择保存，不是整个磁盘或完整运行环境的镜像。迁移本地模型时，记录模型来源、版本、量化、引擎与加载设置，并单独保留必要文件；恢复插件设置不证明推理资源已恢复。

::: info 密钥与口令
不包含密钥的备份仍可保存服务配置，恢复后需重新填写凭据。备份口令无法找回，请单独保管；OAuth 登录在恢复后需要重新授权。
:::

本地保留数量可在设置中调整，超额副本按规则清理；不会因此自动删除云端备份或已导出的副本。

## 恢复备份

1. 保存当前工作，必要时先为当前状态创建备份。
2. 从「查看备份」选择恢复，或「导入备份」选择文件。
3. 选择恢复范围；包含密钥时输入口令。
4. 确认「重启并恢复」，重启后检查任务、文件与配置。

恢复会覆盖匹配记录或同名文件，其他内容保留，并保留恢复前的数据副本。恢复的自动化、插件和 Skills 需要重新启用，OAuth 需要重新登录。插件的外部资源授权可能需要重新选择；本地模型与引擎需单独检查，不能仅凭插件页面出现就认定恢复完成。

## 使用自己的云备份存储

在「数据存储」开启云备份，选择 WebDAV 或 S3 兼容存储，填写地址、备份目录与认证信息。先「测试连接」，再选择内容、频率并「保存并备份」，最后检查实际备份状态。

云备份遵循备份选择，不会额外包含模型权重或外部目录。它是副本，不是多人实时编辑或双向文件同步；自动备份需要 Lexora 保持运行。

## 更换数据目录

通过「数据目录 → 更改目录」选择目标并确认重启搬迁。使用空目录或这份数据曾使用的位置，确保足够空间。

搬迁应用数据与创建选择性备份不是同一操作；外部引用不会变成应用托管文件。搬迁期间不要手动移动目录。发生错误时保留原位置和备份，检查权限、空间与提示，正常使用前不要删除旧数据。

问题排查见[常见问题](./troubleshooting#备份、恢复或搬迁未完成)。
