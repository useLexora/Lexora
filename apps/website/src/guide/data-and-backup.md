# 数据与备份

Lexora 开源自己的代码，不替你“开源”你的代码。项目文件在本机处理，任务与配置也保存在本机；使用在线模型或外部工具时，调用需要的内容会发送给你选择的服务。

## 哪些内容保存在本机

| 内容 | 存放或发送方式 |
| --- | --- |
| 任务、对话、伙伴与应用设置 | 保存在当前 Lexora 数据目录 |
| 托管工作文件 | 位于 Lexora 数据目录内 |
| 自己选择的外部工作目录 | 仍在原磁盘位置，不会因为加入空间而整体上传 |
| API Key 和登录凭据 | 使用操作系统提供的加密能力在本机保存 |
| 在线模型请求 | 上下文直接发送到配置的服务地址，不经 Lexora 云端中转 |
| MCP 与插件的外部调用 | 相关数据发送给所连接或获准访问的服务 |
| 云备份 | 仅在你配置并启用后，写入指定的 WebDAV 或 S3 存储 |

任务上下文可能包含对话、引用内容和工具读取的代码或文件片段。因此“本地优先”不表示使用远程模型时完全没有数据离开电脑。

## 查看数据目录与占用

打开「设置 → 数据存储」。顶部可以查看当前数据目录、打开文件夹，并按分类查看空间占用。

统计不包含所有外部工作目录。清理前先分清任务文件、缓存、日志和备份的用途；不要直接删除正在使用的数据库或配置文件。

## 创建一份本地备份

1. 在「数据存储」的备份区域点击「创建备份」。
2. 选择需要保存的内容，例如任务与空间、伙伴、模型服务、Skills、插件和应用设置。
3. 如需包含密钥，开启对应选项，并设置至少 8 位的备份口令。
4. 等待完成后，点击「查看备份」，确认出现新的备份记录。

「托管工作文件」仅包含 Lexora 数据目录内的工作文件，不会把整个外部项目目录一起备份。外部原稿、代码仓库和其他资料仍需要自己的备份方式。

::: info 密钥与口令
不包含密钥的备份仍可保存服务配置，恢复后重新填写凭据即可。备份口令无法找回，请单独保管；OAuth 登录在恢复后需要重新授权。
:::

本地备份保留数量可以在设置中调整。超额副本会按界面说明清理；云端备份和已经导出的副本不随这一数量自动删除。

## 恢复备份

1. 先确认当前重要工作已保存，需要时为当前状态再创建一份备份。
2. 从「查看备份」选择恢复，或通过「导入备份」选择已有文件。
3. 选择要恢复的内容；包含密钥时输入备份口令。
4. 确认「重启并恢复」。重启后检查任务、配置与成果，再启用需要的扩展或计划。

恢复会覆盖相匹配的记录或同名文件，其他内容保留。应用会保留恢复前的数据副本；恢复的自动化、插件和 Skills 需要重新启用，OAuth 需要重新登录。

## 使用自己的云备份存储

在「数据存储」中开启云备份，选择 WebDAV 或 S3 兼容存储，填写服务地址、备份目录与认证信息。

先点击「测试连接」，确认备份目录可以读写；再选择备份内容、频率，点击「保存并备份」。保存后检查最近备份状态，而不仅是连接测试结果。

云备份保存的是备份副本，不是多人实时编辑，也不是外部文件夹的实时双向同步。自动备份需要 Lexora 保持运行。

## 更换数据目录

需要把应用数据移到其他磁盘时，使用「数据目录 → 更改目录」，按提示选择目标，再确认重启搬迁。选择空目录或这份数据曾经使用的位置，并确保有足够空间。

搬迁期间不要手动移动目录。若界面提示未完成，先检查权限、可用空间与错误说明；原位置的数据仍应保留，确认恢复正常前不要手动删除旧目录。

恢复或搬迁遇到问题，可以从[常见问题](./troubleshooting)继续排查。
