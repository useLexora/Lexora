# Skills 与 MCP

Skills 用来带上工作方法，MCP 用来连接外部工具。它们可以配合使用：例如用一个资料整理 Skill 约定输出格式，再通过 MCP 查询你使用的资料服务。

## 先选对扩展方式

| 你需要的是 | 适合使用 |
| --- | --- |
| 一套可反复遵循的步骤、写作规范或配套资料 | Skill |
| 一个已有服务提供的查询或操作能力 | MCP |
| 工作台里的页面、面板、主题或专用交互 | [插件](./plugins) |

## 安装一个 Skill

进入「设置 → Skills」：

1. 选择「全局」，或选择「空间」并指定目标空间。
2. 点击「安装 Skill」，选择本地文件夹或公开 GitHub 仓库。
3. GitHub 来源可以指定分支或标签，以及 Skill 所在子目录。
4. 先预览发现的 Skills，阅读名称、描述、来源与文件。
5. 选中需要的条目，确认安装。

安装会复制资源文件，不会在安装时执行其中的脚本。安装完成后，在后续任务运行中生效。

### 全局还是空间？

各个任务都需要的方法适合装到全局；只与某个项目有关的方法适合装到空间。工作目录也可能自带 Skills。遇到同名条目时，查看界面的来源与覆盖提示，确认当前实际使用哪一份。

## 在任务中使用 Skill

在输入框输入 `/skills`，从当前任务可用的 Skills 中选择，再附上具体目标和材料。也可以为某个伙伴设置它可用的 Skills，让工作方法与角色职责对应。

例如选择资料整理方法后补充：

> 整理工作目录里的旅行笔记。保留地点来源，输出路线和待确认信息，保存到「草稿」目录。

Skill 提供方法，不会自动授予额外的文件或工具权限。更新或移除时，如果提示正在使用，等相关运行结束再操作。

### 把自己的方法留下来

点击「创建 Skill」，或在任务中明确描述常用流程，让 Lexora 帮你整理成可复用的方法。先说清输入、步骤、交付格式和容易犯的错误，再用一份小材料验证。

## 添加一个 MCP 连接

先从工具提供方取得连接说明，再进入「设置 → MCP」。

| 连接方式 | 要填写什么 | 运行位置 |
| --- | --- | --- |
| 本地命令（Stdio） | 启动命令、参数、必要的环境变量 | 在你的电脑上运行，需要相应程序已安装 |
| 远程服务（HTTP） | 服务地址、必要的请求头或 Bearer Token | 请求发送到该服务 |

1. 点击「添加连接」，选择对应方式并填写配置。
2. 保存后连接默认停用，可以先点击「测试连接」。本地命令在测试或启用前可能要求确认执行。
3. 查看工具列表，确认包含你想使用的能力。
4. 启用连接，再回到任务提出一个范围明确的小请求。

::: tip 测试成功还不等于已经启用
停用状态也可以测试并缓存工具列表。只有启用并连接成功后，对话才能使用；缓存列表不代表当前连接仍然正常。
:::

### 已有 JSON 配置

点击「导入 JSON」，粘贴含有 `mcpServers` 的配置，每个连接指定 `command` 或 `url`。先检查预览再保存；导入不会自动启动连接。

### 工具使用方式

通常先保留默认的「按需发现」。需要了解高级选项时，可以展开下面的说明。

::: details 按需发现、直接提供与代码编排
- **按需发现**：需要时通过工具搜索加载定义。
- **直接提供**：每轮都提供工具定义，工具较多时会增加上下文占用。
- **仅通过代码编排**：只允许通过 Codemode 发现和调用，需要在「设置 → 运行时」开启对应能力。
- **工具已隐藏**：保留连接配置，但不向模型或脚本提供工具。
:::

## 连接正常，伙伴仍然不能调用？

依次检查连接是否启用、工具使用方式是否可用、伙伴是否允许使用该工具，以及当前任务权限。可以用 `/mcp` 打开连接状态，尝试重新连接。

停用 MCP 对所有任务生效，会阻止新的调用，并保留配置、凭据和工具缓存。不要在其他任务仍需要它时随意停用。

需要让工作按时间重复执行，继续阅读[自动化](./automations)。
