# 常见问题

先保存任务或设置页的具体错误，确认失败阶段，再做最小检查。不要以清空数据目录、关闭所有保护或重复提交外部操作作为第一步。

## 输入框显示“未发现模型”

1. 在「设置 → 模型服务」确认服务已完成认证并启用。
2. 启用至少一个可用的**对话模型**；只有语音或生图模型不会出现在任务的聊天选择中。
3. 返回任务重新选择模型；只有某位伙伴不可用时，检查它的模型选择。
4. 插件模型还要检查插件是否启用、资源和引擎是否准备完成。

只保存 Key 或同步目录不代表模型已启用。见[连接模型](./settings-and-models)。

## 发送后出现认证、额度或连接错误

- **认证**：核对 Key 所属服务、有效性与权限，或重新进行 OAuth。
- **额度**：检查 API 余额和限额，不只看聊天订阅。
- **模型不存在**：核对模型 ID、用途、接口协议和账号权限。
- **超时**：检查服务地址、代理和服务状态；外部本地服务器需保持运行。

先用不带附件、不调用工具的短消息验证，再逐项恢复原条件。详情见[应用设置](./app-settings#应用代理与下载代理)。

## 任务看起来没有继续

区分以下状态：

| 状态 | 下一步 |
| --- | --- |
| 正在执行或等待资源 | 查看最近进度与工具记录，不要连续发送同一请求 |
| 等待审批 | 处理审批卡，确认目标和授权范围 |
| 等待用户回答 | 打开问题卡，提交选项或自定义回答；关闭卡片不等于回答 |
| 消息排队或已暂停 | 检查队列，按需要发送或补充；停止后的队列可能保留为暂停 |
| 报错或结果未知 | 查看错误和已完成操作，先核对实际结果 |

回答问题是补充信息，不等于批准工具权限。停止或取消也不证明外部操作已回滚；对于付款、发布、生成图片等操作，先核对结果再重试。

## 文件没有保存到想要的位置

检查当前空间和工作目录，展开工具记录核对完整路径，并打开实际文件。模型说“已保存”不是文件存在的证明。

说明目标，例如“保存到当前工作目录的「草稿/周末路线.md」”。只读、额外目录和沙箱不可用问题见[执行权限](./permissions)。不要把“路径不存在”直接当成权限错误。

## 图片不能识别或生成

- 看图失败：检查当前模型的图片能力、图像设置中的识图选择和图片是否确实可读。
- OCR 能读文字但答不出颜色或状态：改用视觉理解，不要只提供转录结果。
- 生图失败：检查生成模型、认证、额度、参考图支持及目标路径。
- 显示“结果未知”或“图片保存未完成”：先查看已有产物和服务记录，**不要盲目重复提交**。

保存成功后仍需检查实际图片。见[图片理解与生成](./images)。

## 语音输入或朗读不可用

先在「设置 → 语音」分别使用麦克风测试、短句转写和试听，以区分设备、转写与播放问题。

检查麦克风权限、输入输出设备、所选模型、声音 ID、额度与网络。本地来源再检查引擎状态。系统没有可用声音时，可以检查系统语音组件或选择模型来源。中断后先核对已识别文字，见[语音](./speech)。

## 本地模型或引擎无法启动

1. 区分本地模型插件与外部兼容 API；前者看插件状态，后者看外部服务。
2. 核对操作系统、架构、引擎版本、模型格式与后端支持。
3. 检查下载是否完成、文件是否仍存在、授权是否有效，以及内存、显存和磁盘空间。
4. 先用较小、已知受支持的模型或请求验证，保留具体加载错误。

插件已安装不代表引擎和模型就绪。不要反复下载同一大模型或清空资源来猜测原因；某个模型在其他设备成功不证明本机支持。见[本地模型](./local-models)。

## 网页读不到或搜索失败

核对来源开关、网络、限流和错误，区分页面需要脚本、登录还是远程提取配置缺失。后台渲染不继承登录状态；需要登录操作时使用交互浏览器。不要把部分正文当成全文，见[搜索与浏览网页](./web-browsing)。

## 已安装的 Skill 或 MCP 工具不可用

Skill 检查所属范围、启用状态、同名覆盖和伙伴的能力选择；修改后刷新，内容变化时重新选择。

MCP 检查是否启用并真正连接。缓存工具列表和一次测试成功都不证明当前任务可用；仅通过代码编排的连接还需要对应运行时能力。见[Skills 与 MCP](./skills-and-mcp)。

## 插件安装了，但打不开或没有变化

在「插件 → 已安装」检查启用状态、活动版本和错误。新版本可能已安装但未切换；入口也可能是命令、工具或主题，而不是独立页面。

自己制作的插件可回到原任务，提供具体错误与复现步骤继续修复。安装和权限见[插件](./plugins)。

## 自动化没有按时执行

1. 确认计划启用、未暂停，检查下一次执行时间和日期区间。
2. 确认电脑当时唤醒，Lexora 未完全退出。
3. 查看记录，区分未触发、失败和完成。
4. 检查空间、固定模型、工具及预先授权；后台不能等待审批，缺失授权会失败。
5. 修复后使用「立即运行」验证，不改变原计划。

见[自动化](./automations)。

## 备份、恢复或搬迁未完成

保留错误，检查空间、目录权限和口令；先处理活动任务或待完成的目录操作。云备份连接测试成功不等于上传完成。

不要清空数据目录。保留备份与原数据，检查恢复范围；恢复插件不等于恢复大模型权重与引擎，见[数据与备份](./data-and-backup)。

## 检查或安装更新失败

- 核对版本、更新通道、网络与代理；“上次检查结果”不是本次检查成功。
- 当前平台或安装方式可能不支持应用内下载，按提示前往正式发布页。
- 安装包未取得或校验失败时，先修复下载问题，不手动绕过校验。
- 自动下载不会自动安装；关闭自动检查时后台下载也暂停。
- 从 Beta 切回稳定版不会自动降级；保留备份，不要随意用旧版打开新数据。

设置说明见[应用更新](./app-settings#稳定版与尝鲜版更新)。

## 仍然无法解决

到 [GitHub Issues](https://github.com/useLexora/Lexora/issues) 提供版本、操作系统与架构、操作步骤、预期和实际结果，以及完整错误。涉及模型时附服务类型与模型 ID，不附密钥。

「设置 → 日志」可查看应用日志。分享前移除账号、凭据、私人路径、任务和文档内容；不要上传整个数据目录。
