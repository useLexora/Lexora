# 常见问题

先看任务或设置页给出的具体错误，再按对应步骤检查。多数问题可以从模型连接、执行状态、文件位置和扩展启用情况中找到原因。

## 输入框显示“未发现模型”

1. 打开「设置 → 模型服务」，确认已经添加服务。
2. 完成认证，并在模型列表启用至少一个可用模型。
3. 确认服务已启用，再回到任务重新选择模型。
4. 如果只有某位伙伴不可用，检查它在当前任务中的模型选择。

完整流程见[连接模型](./settings-and-models)。只填了 API Key，或只同步了模型列表，都不等于已经启用模型。

## 发送后出现认证、额度或连接错误

- **认证错误**：检查 Key 是否属于当前服务，是否失效；OAuth 可以重新授权。
- **余额或额度不足**：到服务商控制台确认 API 额度，不要只看聊天网页的订阅状态。
- **模型不可用**：确认模型 ID 和账号权限；自定义服务尤其要核对实际支持的接口。
- **超时或无法连接**：检查服务地址、网络代理；本地模型服务需要保持运行。

先用一条不带附件、不调用工具的简短对话验证，成功后再逐项恢复原任务条件。

## 任务看起来没有继续

先看状态：正在执行、等待确认和消息等待发送是三种不同情况。

等待确认时处理审批卡片；消息排队时检查是否需要立即发送；连接报错时先恢复模型或工具。如果决定停止，等当前执行结束后查看已完成操作，再继续任务，避免重复提交相同的外部动作。

## 文件没有保存到想要的位置

查看任务当前空间和工作目录，再展开文件工具的执行记录确认路径。模型回复里说“已保存”，仍要以实际文件为准。

把期望位置说完整，例如：“保存到当前工作目录的「草稿/周末路线.md」。”若处于本机只读模式，先按需要调整[执行权限](./permissions)。

## 已安装的 Skill 或 MCP 工具不可用

Skill 先检查所属范围、是否启用、同名覆盖提示和伙伴的能力选择。修改了文件后可以刷新；遇到内容已变化的提示，重新选择再发送。

MCP 先检查是否启用并成功连接。缓存工具列表不能证明连接正常；测试成功但仍停用的连接，也不会供任务调用。高级模式为“仅通过代码编排”时，还要开启对应的运行时能力。

操作路径见[Skills 与 MCP](./skills-and-mcp)。

## 插件安装了，但打不开或没有变化

查看「插件 → 已安装」中的启用状态、当前版本与错误。新版本可能已经安装，但还没切换使用。插件提供的入口也可能是命令、工具或主题，而不是独立页面。

自己制作的插件可以回到原任务，附上具体错误、复现步骤和当前表现继续修复。不要只说“不能用”。

## 自动化没有按时执行

1. 确认计划已启用且未暂停，检查下一次执行时间与生效日期区间。
2. 确认电脑当时处于唤醒状态，Lexora 没有完全退出。
3. 查看运行记录，区分未触发、失败、等待确认与已完成。
4. 检查关联空间、固定模型与所需工具是否仍可用。
5. 使用「立即运行」验证修复结果，它不会改变原计划。

更多说明见[自动化](./automations)。

## 备份、恢复或搬迁未完成

先保存错误提示，检查剩余空间、目录权限与备份口令。当前任务忙或已有待处理目录操作时，先完成相应事项再重试。云备份连接测试成功，不等于备份已经上传完成，要检查备份状态。

不要为了重试直接清空数据目录。已有备份与原位置的数据应保留，直到确认应用恢复正常。具体范围见[数据与备份](./data-and-backup)。

## 仍然无法解决

可以到 [GitHub Issues](https://github.com/useLexora/Lexora/issues)反馈，尽量提供：

- Lexora 版本、操作系统与架构。
- 从哪个页面开始、做了哪些操作。
- 预期结果与实际结果，以及完整的错误提示。
- 能帮助定位的截图或日志片段。

「设置 → 日志」可查看应用日志。分享前检查并移除 API Key、账号信息、私人路径和任务内容；不要直接上传整个数据目录。
