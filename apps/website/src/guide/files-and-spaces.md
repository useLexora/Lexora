# 文件与空间

空间组织相关任务，工作目录保存实际文件。把两者分清，就能知道任务归在哪里、成果存在哪里，以及下一次从哪里继续。没有选择空间的任务也有自己的托管工作目录，不必先创建空间才能写文件。

## 给一组工作建立空间

例如为周末出行建立“旅行计划”空间，把路线、行李和游记分别放进三个任务。这样任务各有重点，也能回到同一个主题下查找。

1. 在任务侧栏新建空间，填写容易识别的名称。
2. 需要使用已有文件时，为空间选择本地工作目录。
3. 在空间内新建任务，或在新任务的输入区选择该空间。

选择工作目录也意味着信任该目录中的上下文文件与 Skills。只选择这次工作需要的目录；额外批准某个目录的访问，不等于自动把其中所有内容加入上下文。

## 准备一个清楚的目录

可以把旅行资料这样组织：

```text
旅行计划/
├── 资料/
│   └── 城市漫步笔记.md
└── 草稿/
```

然后给出相对路径：

> 参考「资料/城市漫步笔记.md」，把周末路线保存到「草稿/周末路线.md」。原始笔记保持不变。

这种方式既方便模型找到材料，也方便你检查成果。文件树对应磁盘上的文件，重命名、复制或移动会作用于实际文件。

## 并排打开对话与资料

通过任务标题栏的窗格菜单向左、右、上、下分屏，也可以把任务拖到目标边缘。文件在资料区域打开后，可以与任务并排查看。多个任务分别保留自己的上下文和输入区，分屏本身不会互相分享材料。

想修改某段内容，直接在预览中选中并引用到目标任务。多分屏时先确认引用进入了正确的输入框，再发送要求。

## 选择打开方式

从文件入口的「打开方式」选择当前可用的提供方。内置预览适合文本、Markdown、图片等受支持内容；已安装的插件可以为特定文件提供编辑器。也可以在「设置」的文件打开方式页面，按后缀设置默认提供方；内联预览和独立打开可分别设置。

安装插件时检查它申请的文件关联，不必接受所有默认选项。插件停用或不可用时，默认选择可能回退到内置方式，这不代表文件丢失。需要 DOCX、XLSX、PPTX 或 PDF 的编辑与引用写回，见[文档处理](./documents)。

## 文件引用、附件与任务引用

| 方式 | 适合什么时候使用 |
| --- | --- |
| 文件引用 | 记录原文件路径，按需读取；不是把全部正文自动放进输入 |
| 选区引用 | 保存所选内容和来源，便于讨论或定位修改 |
| 附件副本 | 保存本轮提供的字节快照；修改副本不等于修改原文件 |
| 任务引用 | 按需查阅另一个任务中获准引用的内容 |

从本机选择或拖入有路径的文件通常保留原文件引用；粘贴图片等没有原路径的输入会保存为附件副本。受支持的媒体还可能生成供模型读取的快照，是否直接理解取决于模型、格式与大小；“已附加”不等于“已读完”。

文件或内容被引用，不会赋予任意目录访问权限。遇到访问请求时，确认是本次工作需要的位置即可。历史引用保留当时的内容；原文件后来改变时，修改前需要重新核对当前内容。

## 找回与继续已有工作

给任务起能描述目标的名字，例如“周末步行路线”而不是“新任务”。常用任务可以置顶；任务按标题或空间名称搜索，空间也可通过目录路径找到。这不是消息全文搜索，详见[任务历史](./ai-chat#查找历史任务)。

下次打开任务时，可以查看已有对话和执行记录，再告诉伙伴从哪个成果接着做。应用重启后的持续工作指的是保留进展，不代表所有中断的外部命令都会自动重新执行。

## 确认内容真的写入文件

要求修改时说清楚是原件还是新副本，例如“更新草稿/周末路线.md，不改原始笔记”。编辑器里的未保存内容、对话中的文本和磁盘上的文件是不同状态。

完成后核对保存位置，再打开实际文件检查。遇到外部修改冲突，先比较当前内容，不要直接覆盖；停止任务和切换对话分支都不会自动撤销磁盘写入。插件编辑器的保存与导出规则以其提示为准。

## 哪些文件需要自己备份

Lexora 的数据备份可以包含托管工作文件，但不包含你选中的整个外部工作目录。旅行目录、代码仓库、设计原稿等外部文件，应继续使用自己的文件备份或版本管理方式。

具体范围与恢复方法见[数据与备份](./data-and-backup)。
