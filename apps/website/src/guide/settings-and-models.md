# 连接模型

模型服务负责理解和生成内容，Lexora 负责把对话、文件、工具和执行过程放进同一个工作台。使用前，需要先让一个模型服务完成认证，并启用你要使用的模型。

## 选择接入方式

进入「设置 → 模型服务 → 添加服务」。根据手头的接入信息选择：

| 你已有的服务 | 选择方式 | 需要准备 |
| --- | --- | --- |
| 列表中的服务商 | 内置服务 | API Key，或该服务支持的 OAuth 账号 |
| 兼容接口、企业网关 | 自定义 API | API 类型、服务地址、认证信息和模型 ID |
| 本机或局域网的模型服务 | 自定义 API | 已启动且可访问的兼容 API 地址、模型 ID，以及服务要求的认证信息 |

Lexora 不负责安装或启动本地模型服务。先按该服务的说明启动，再把它作为连接添加进来。

## 添加内置服务

1. 在「内置服务」中搜索服务商，点击「添加」。
2. 在「配置连接」中选择「配置 API Key」或「使用 OAuth」。API Key 应来自对应服务商的控制台；OAuth 按界面提示在浏览器完成授权。
3. 进入「配置模型」，开启需要的模型。
4. 点击「完成并启用」，返回任务页选择模型，发送一条简单消息验证连接。

服务显示“已保存 API Key”表示凭据已经保存。是否能完成请求，还取决于密钥有效性、模型权限、余额和网络；用一条简短对话检查最直接。

## 添加自定义 API

在「自定义 API」中填写显示名称、标识符、API 类型与服务地址，再按向导配置认证。

- **显示名称**帮助你区分连接，例如“家里的模型服务”。
- **标识符**用于区分配置，按表单要求填写且不要与已有服务重复。
- **API 类型**要与服务实际提供的协议一致。兼容某一种接口，不代表兼容所有接口。
- **服务地址**填写服务文档给出的 API 基础地址，而不是聊天网页的网址。
- **模型 ID**使用服务端接受的名称，不要只填写自己起的显示名称。

认证完成后，支持模型发现的服务可以点击「同步模型」；否则使用「手动添加模型」。添加或同步之后，还要显式启用要使用的模型。

::: details 什么时候需要高级设置？
只有服务要求额外请求头，或你明确需要覆盖模型参数时才调整。上下文窗口、最大输出和输入能力应与服务实际限制一致；把数值调大不会提高服务端上限。先保留默认值，让最小请求跑通，再逐项调整。
:::

## 连接本地 AI 模型

如果已经在本机或局域网运行模型服务，可以用它提供的兼容 API 接入 Lexora：

1. 先启动模型服务，确认它已经加载模型并开放 API。
2. 添加「自定义 API」，填写服务的协议、基础地址与认证信息。`localhost` 指运行 Lexora 的这台电脑；另一台电脑上的服务需要填写其可访问的地址。
3. 同步或手动添加模型，启用后发送一条简短消息检查连接。

本地模型负责推理，Lexora 负责组织任务与执行工具。模型在本机运行不等于所有操作都离线：联网工具、远程 MCP 和备份仍可能使用网络。

## 在任务和伙伴之间选择模型

任务中的模型选择与伙伴有关。可以在伙伴配置里设置默认模型，也可以在任务中为参与的伙伴选择模型。使用大肥鱼、小克或小白的头像，不会自动为它连接对应服务。

简单整理可以先用响应较快的模型；需要读取图片、处理复杂材料或使用工具时，选择支持相应能力的模型。不要仅凭模型名字判断能力，检查模型配置与服务说明。

## 检查用量与连接问题

「设置 → 使用情况」可以查看 Lexora 记录的模型用量，并按任务或模型观察消耗。服务商的账单和额度仍以其控制台为准。

| 现象 | 先检查 |
| --- | --- |
| 任务里没有模型 | 服务是否完成配置，是否至少启用了一个可用模型 |
| 提示需要认证 | API Key 是否有效，OAuth 是否需要重新授权 |
| 模型找不到 | 模型 ID 是否准确，当前账号是否有权限使用 |
| 连接超时 | 服务是否运行，地址、网络与代理是否正确 |
| 能对话但不能处理图片 | 当前模型和接入协议是否支持图片输入 |

连接成功后，回到[第一个任务](./quick-start)；想为不同伙伴分配模型，继续阅读[伙伴与协作](./companions)。
