# 任务与对话

任务承载一个持续推进的目标。你可以在同一任务中补充材料、查看工具操作、修改成果；只有工作主题或需要的上下文明显不同，才有必要另开任务。

## 让第一句话更容易执行

可以按“目标、材料、成果”组织要求。例如：

> 根据工作目录里的旅行笔记，整理一份两天的步行路线。保留地点来源，不确定的信息单独列出。保存为「周末路线.md」，不要改动原始笔记。

这里说清了要完成什么、参考什么、产出什么，以及哪些内容应保留。你不需要一开始想好全部细节，先拿到一个可检查的结果，再逐步完善。

## 读懂任务进行到哪里

对话里既有伙伴的回复，也有执行过程。展开工具记录可以查看具体操作与结果；文件成果可以直接打开预览。

| 当前状态 | 你可以做什么 |
| --- | --- |
| 正在执行 | 查看进展，补充要求，或停止本轮工作 |
| 等待确认 | 打开审批卡片，核对目标、参数与权限范围 |
| 消息等待发送 | 查看排队内容，取消排队或选择立即发送 |
| 已完成 | 检查答案与文件，继续提出修改 |
| 失败或已取消 | 查看最后的错误与已完成操作，确认现状后再继续 |

停止执行不会自动撤销已经写入的文件，也不会撤回外部服务已经完成的操作。需要回退时，先查看变更和实际文件。

## 运行时补充要求

任务工作期间仍可以输入。后续消息进入队列时，界面会显示「等待发送」；它还没有被执行。可以取消排队，或用「立即发送」把新的要求提交到当前运行中。

适合排队的是下一步工作，例如“整理完路线后，再列行李清单”。当前方向需要调整时，说明新的约束，例如“先不要预订，只比较路线”。已经完成的动作仍需单独检查。

## 引用具体内容

“把这里改一下”需要一个明确的“这里”。引用会把选中的内容和来源带进输入框：

1. 在对话、文本文件或 Markdown 预览中选中一段文字。
2. 右键选择引用操作；文件引用可选择要发送到的目标输入框。
3. 检查输入框里的引用卡片，补充要求后发送。

内置浏览器还支持元素拾取：选中需要讨论的网页元素，再引用到对话。引用保留当时的内容和来源；来源之后变化时，重新定位可能与引用时不同。

## 引用已有任务

需要沿用另一个任务的成果时，把它作为任务引用附加到输入中，并说明想沿用哪部分。例如：“参考之前的路线任务，只提取已经确认的地点，另写一份出行清单。”

引用让模型可以按需查阅相应上下文，不表示它已经读完全部内容，也不表示所有历史任务都会自动开放。

## 用分支尝试另一种方向

想保留当前答案，再试另一种写法，可以从已有对话创建分支，并在分支画布中查看和继续。适合比较两种文章结构、设计方向或解题方式。

::: info 对话分支与磁盘文件
分支保留对话路径，磁盘上的文件不会随分支回退。比较不同版本时，让伙伴保存成不同文件，例如「路线-轻松版.md」与「路线-紧凑版.md」。
:::

## 常用输入命令

在输入框输入 `/` 查看当前可用命令。常用项包括：

| 命令 | 用途 |
| --- | --- |
| `/skills` | 从当前任务可用的 Skills 中选择工作方法 |
| `/mcp` | 查看 MCP 连接状态，快速启停和重连 |
| `/status` | 查看当前对话状态 |
| `/compact` | 压缩较早上下文，可以附上希望保留的重点 |
| `/review` | 以只读方式审查当前工作，给出风险和建议 |

部分命令需要已有对话，并且不能同时携带引用、附件或 Skill；以输入框的可用状态为准。

## 检查结果，然后接着做

核对文件路径、事实来源与实际内容。模型说“已经保存”时，打开文件看一遍；需要修改时，优先引用有问题的部分，保留已经满意的内容。

需要把资料摆在旁边，继续阅读[文件与空间](./files-and-spaces)；需要不同伙伴接手，阅读[伙伴与协作](./companions)。
