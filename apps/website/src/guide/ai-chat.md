# 任务与对话

任务承载一个持续推进的目标。你可以在同一任务中补充材料、查看工具操作、修改成果；只有工作主题或需要的上下文明显不同，才有必要另开任务。

## 查找历史任务

从任务历史重新打开已有工作，常用任务可以置顶。使用「搜索任务和空间」时：

- 任务按标题或所属空间名称匹配。
- 空间可按名称、主工作目录或附加目录路径匹配。
- 这不是所有消息正文的全文搜索；搜不到一句话，不代表它不在历史里。

给任务起一个描述目标的名称，例如“周末步行路线”。打开后先看已有结论和产物，再说明接下来要改什么。

## 让第一句话更容易执行

可以按“目标、材料、成果”组织要求。例如：

> 根据工作目录里的旅行笔记，整理一份两天的步行路线。保留地点来源，不确定的信息单独列出。保存为「周末路线.md」，不要改动原始笔记。

这里说清了要完成什么、参考什么、产出什么，以及哪些内容应保留。你不需要一开始想好全部细节，先拿到一个可检查的结果，再逐步完善。

## 读懂任务进行到哪里

对话里既有伙伴的回复，也有执行过程。展开工具记录可以查看具体操作与结果；文件成果可以直接打开预览。

| 当前状态 | 你可以做什么 |
| --- | --- |
| 正在执行 | 查看进展，补充要求，或停止本轮工作 |
| 待回答 | 展开问题卡片，填写并提交回答 |
| 等待确认 | 打开审批卡片，核对目标、参数与权限范围 |
| 消息等待发送 | 查看排队内容，取消排队或选择立即发送 |
| 已完成 | 检查答案与文件，继续提出修改 |
| 失败或已取消 | 查看最后的错误与已完成操作，确认现状后再继续 |

停止执行不会自动撤销已经写入的文件，也不会撤回外部服务已经完成的操作。需要回退时，先查看变更和实际文件。

## 运行时补充要求

在「设置 → 运行时 → 执行行为」选择「工作中发送消息」的默认方式：

| 方式 | 何时处理 | 适合的要求 |
| --- | --- | --- |
| 补充当前工作（默认） | 在可接收输入的执行边界加入当前工作 | “先不要预订，只比较路线” |
| 排队 | 等目标伙伴的当前工作结束后处理 | “整理完路线后，再列行李清单” |

排队项显示「等待发送」，尚未交给伙伴处理。可取消排队；在允许时用「立即发送」把该项补充到原目标的当前工作。它不会撤销已完成操作，也不保证打断正在进行的工具调用。修改默认方式不改变已经排队的消息。

目标已经结束、配置改变或消息暂停时，先看界面提示；不要把“已接收”当作“已经完成”。需要停止时使用停止操作，而不是只发送“停一下”。

## 逐题回答伙伴的问题

伙伴需要你确认需求时，任务输入区会出现「待回答」入口；这与批准工具执行的权限卡片不同。

1. 展开问题，按题型单选、多选或填写文字，也可以给出自定义回答。
2. 同一组有多题时，用前后箭头逐题填写；切换不会提交或清空已填内容。
3. 填完所有必需答案后，点击「提交回答」。有多组请求时，分别切换并处理。

「推荐」只是建议，不会替你选择。「不回答」关闭整组请求，不是跳过当前题，也不代表同意。收起卡片会保留本次未提交内容，但不要依赖关闭应用后恢复这些草稿。

提交后的问答可在任务记录中查看；若显示“回答已保存，未能送达”，使用重试入口，不必重填。普通消息不代替这组问题的显式回答；回答也不会授予文件、网络或工具权限。

## 引用具体内容

“把这里改一下”需要一个明确的“这里”。引用会把选中的内容和来源带进输入框：

1. 在对话、文本文件或 Markdown 预览中选中一段文字。
2. 右键选择引用操作；文件引用可选择要发送到的目标输入框。
3. 检查输入框里的引用卡片，补充要求后发送。

## 引用已有任务

需要沿用另一个任务的成果时，把它作为任务引用附加到输入中，并说明想沿用哪部分。例如：“参考之前的路线任务，只提取已经确认的地点，另写一份出行清单。”

通过输入区的任务引用入口选择目标，发送前核对任务名称与所需内容。引用让模型可以按需查阅已引用范围，不表示它已经读完全部内容，也不会自动开放所有历史任务或 NPC 的私有过程。

## 用分支尝试另一种方向

想保留当前答案，再试另一种写法，可以从已有对话创建分支，并在分支画布中查看和继续。适合比较两种文章结构、设计方向或解题方式。

::: info 对话分支与磁盘文件
分支保留对话路径，磁盘上的文件不会随分支回退。比较不同版本时，让伙伴保存成不同文件，例如「路线-轻松版.md」与「路线-紧凑版.md」。
:::

## 常用输入命令

在输入框输入 `/` 查看当前可用命令。常用项包括：

| 命令 | 用途 |
| --- | --- |
| `/skills` | 从当前任务可用的 Skills 中选择工作方法 |
| `/mcp` | 查看 MCP 连接状态，快速启停和重连 |
| `/status` | 查看当前对话状态 |
| `/compact` | 压缩较早上下文，可以附上希望保留的重点 |
| `/review` | 以只读方式审查当前工作，给出风险和建议 |

部分命令需要已有对话，并且不能同时携带引用、附件或 Skill；以输入框的可用状态为准。

## 检查结果，然后接着做

从回复的产物入口打开交付文件，核对路径、内容与事实来源；必要时展开对应执行记录查看错误和变更。模型说“已经保存”时，实际打开文件确认，不只看完成状态。没有产物卡片时，可以要求给出已核实的保存位置。

需要修改时，优先引用有问题的部分，保留已经满意的内容。Office 文档还要区分编辑缓冲、保存原件与导出副本，见[文档处理](./documents)。

需要把资料摆在旁边，继续阅读[文件与空间](./files-and-spaces)；需要不同伙伴接手，阅读[伙伴与协作](./companions)。
