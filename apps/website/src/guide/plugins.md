# 使用与制作插件

插件把一次临时需求变成以后随手可用的功能。它可以是一台播放器、一块工作面板、一套主题，也可以是伙伴反复调用的专用工具。

这一章先介绍安装和使用，再带你从一段需求开始制作自己的插件。不需要先学习插件 API。

## 安装已有插件

打开左侧「插件」，可以从「插件市场」浏览插件，也可以安装已有的本地插件包。

1. 在市场中选择插件并发起安装，或通过安装菜单选择「安装插件包」。
2. 查看安装确认中的名称、版本、来源和请求的权限。
3. 确认安装，返回「已安装」查看状态。
4. 根据插件提供的入口，打开页面、面板，或使用相应命令和工具。

市场无法刷新时，可以稍后重试，或安装已获得的本地包。安装成功只表示插件已加入工作台；有些插件还需要在自己的设置里选择文件、连接服务或配置其他选项。

## 从一个小想法开始

先描述最重要的用途和使用方式。范围越清楚，第一版越容易检查。例如：

```text
帮我做一个阅读计时插件。
在工作台面板里显示剩余时间，提供开始、暂停、重置按钮。
默认 25 分钟，到时间后显示完成提示。
先做好这一个流程，生成源码和可安装的插件包。
```

这是供你尝试的需求，生成结果由当前模型和任务执行决定。第一次可以先不加联网、复杂数据或自动化，让一个完整的小流程跑通。

## 从生成到可以使用

制作过程通常分为四步：

1. **描述需求**：说清入口、行为和希望看到的结果。
2. **生成并检查**：伙伴在任务工作目录中编写源码、构建安装包，检查出现的问题。
3. **确认安装**：查看安装请求和权限，确认后加入工作台。
4. **实际使用**：打开插件，逐项操作，再把问题带回原任务修改。

检查计时器时，不只看按钮是否存在，还要试试开始、暂停、重置，以及到时间后的状态。反馈可以具体到：“暂停后数字还在变化，请修复；原来的布局保留。”

## 插件能扩展哪些地方

| 能力 | 可以怎样组合 |
| --- | --- |
| 独立页面、分屏面板、小组件 | 把常用工具放到适合的位置，与任务一起打开 |
| 主题与窗口特效 | 调整工作台的外观和使用氛围 |
| 菜单与输入命令 | 为反复使用的操作提供入口 |
| Agent 指令与工具 | 让伙伴调用文件分析、内容转换等专用能力 |
| 已配置的模型与获准访问的本地文件 | 读取选择的材料，处理内容，再把结果交回任务 |
| 任务事件、定时命令与通知 | 在特定时机执行后续动作，提醒需要处理的事情 |
| 独立设置与私有存储 | 记住插件自己的配置和使用状态 |

这些能力需要插件实际实现，并声明相应权限。插件不能因为安装成功就随意读取任意文件或执行任意系统命令。插件内的定时动作也需要 Lexora 保持运行。

## 更新、停用与卸载

在「已安装」中管理插件。只是暂时不想使用时，可以禁用；重新启用后再打开。安装新版本时，留意版本切换选项，确认当前使用的是哪一版。

普通卸载会保留插件设置、私有数据和视图位置，便于以后重新安装。「卸载并清除数据」会删除这些内容，操作前确认不再需要。

制作插件的任务与源码应保留，方便后续修改或分享。不要把“已安装的插件”当作唯一的源码备份。

## 遇到问题时

- **没有生成安装包**：继续让伙伴检查构建结果，明确要求交付可安装的包和源码位置。
- **安装后找不到入口**：确认插件已启用，再查看它提供的是页面、命令、工具还是主题。
- **提示版本不兼容**：核对当前 Lexora 版本和插件要求，不要仅修改版本号来绕过检查。
- **缺少权限或文件**：检查插件设置和授权范围，把具体错误带回制作任务。
