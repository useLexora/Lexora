# 伙伴与协作

一个人也能完成不少工作；需要不同视角时，可以让多个伙伴参与同一个任务。例如由 Lexora 整理目标，大肥鱼查资料，小克打磨表达，小白检查成果。名字和职责都由你配置。

## 分清主角、配角与 NPC

| 角色 | 怎样参与 | 结果出现在哪里 |
| --- | --- | --- |
| 当前主角 | 接收普通输入，推进任务，按需委派工作 | 当前任务的对话 |
| 配角 | 加入任务后，被点名或接受委派 | 以自己的身份参与任务对话 |
| NPC | 由已绑定它的伙伴派出，处理独立子任务 | 先返回给调用它的伙伴；过程可以在执行详情中查看 |

管理页的「主角」分组存放可参与任务的伙伴定义。进入某个任务后，其中一位是当前主角，其他成员作为配角。NPC 单独管理，不需要加入普通任务成员。

## 创建自己的伙伴

1. 打开左侧「伙伴」，在相应分组点击添加。
2. 选择类型，填写名称和简介，选一个预置头像或上传图片。
3. 设置「行动准则」，明确它处理什么、怎样交付结果。
4. 选择默认模型、可用的直接工具与 Skills。
5. 保存后，将需要参与对话的伙伴加入任务。

简介便于识别角色；真正约定工作方式的是行动准则。例如给负责查资料的伙伴写：

```text
查找与当前问题直接相关的资料，优先使用原始来源。
区分已确认事实、推测和缺失信息。
返回简短结论、来源和仍需核实的问题，不替其他伙伴改稿。
```

## 把伙伴加入任务

在任务的「伙伴」面板添加需要的成员。普通输入发给当前主角；通过输入框选择并点名一位伙伴，可以把本次要求交给它。

切换主角后，下一轮普通输入由新主角接手。已经开始的执行仍属于原来的伙伴，不会因为切换选择器而换人。

<GuideImage src="/landing/screenshots/collaboration-zh.webp" alt="任务执行树显示 Lexora、大肥鱼和小白各自的工作" caption="协作树保留执行者与进展，方便查看哪一位伙伴正在处理哪部分工作。" :width="2539" :height="1764" />

可以先从两位伙伴开始：一位写初稿，一位提出修改意见。分工要具体，尤其在处理同一份文件时，说明谁负责修改、谁只给建议。

## 为主角招募 NPC

在伙伴配置的 NPC 小队中招募需要的角色。内置角色包括探索者、研究员、执行者与审查者；你也可以创建自己的 NPC，设置其行动准则、模型与能力。

NPC 适合范围清楚的子任务，例如“只核对这三个地点的来源，返回有疑问的条目”。主角收到结果后继续推进整体目标。

## 为什么没有按预想协作

- **无法点名**：先确认伙伴已加入当前任务，而不仅仅存在于管理页。
- **不能调用 NPC**：检查该 NPC 是否启用、是否绑定到发起委派的伙伴。
- **工具或 Skill 不可用**：检查连接或安装状态，以及伙伴的能力选择。
- **换了默认伙伴，旧任务没变**：默认伙伴影响新任务；旧任务的当前主角需要单独切换。

每位伙伴的请求都可能消耗模型额度。先用清楚的小分工验证效果，再扩大协作范围。模型设置见[连接模型](./settings-and-models)，权限设置见[执行权限](./permissions)。
