# 伙伴与协作

一个人也能完成不少工作；需要不同视角时，可以让多个伙伴参与同一个任务。例如由 Lexora 整理目标，大肥鱼查资料，小克打磨表达，小白检查成果。名字和职责都由你配置。

## 分清主角、配角与 NPC

| 角色 | 怎样参与 | 结果出现在哪里 |
| --- | --- | --- |
| 当前主角 | 接收普通输入，推进任务，按需委派工作 | 当前任务的对话 |
| 配角 | 加入任务后，被点名或接受委派 | 以自己的身份参与任务对话 |
| NPC | 由已绑定它的伙伴派出，处理独立子任务 | 先返回给调用它的伙伴；过程可以在执行详情中查看 |

管理页的「主角」分组存放可参与任务的伙伴定义。进入某个任务后，其中一位是当前主角，其他成员作为配角。NPC 单独管理，不需要加入普通任务成员。

## 创建自己的伙伴

1. 打开左侧「伙伴」，在相应分组点击添加。
2. 选择类型，填写名称和简介，选一个预置头像或上传图片。
3. 设置「行动准则」，明确它处理什么、怎样交付结果。
4. 选择默认模型、可用的直接工具与 Skills。
5. 保存后，将需要参与对话的伙伴加入任务。

名称与简介帮助伙伴理解身份和分工，行动准则约定具体工作方式；它们都不会扩大权限。例如给负责查资料的伙伴写：

```text
查找与当前问题直接相关的资料，优先使用原始来源。
区分已确认事实、推测和缺失信息。
返回简短结论、来源和仍需核实的问题，不替其他伙伴改稿。
```

## 选择模型与思考强度

伙伴可以设置默认模型，也可以在任务输入区为当前接收者选择模型。任务中的选择不会同时改掉其他伙伴；已有任务的选型也不会因为应用默认模型改变而自动跟随。

模型支持时，可以调整思考强度（推理强度）。较高档位可能增加等待时间与用量，不保证答案更正确；简单整理先用默认，复杂推理再比较。没有该选项或提示原档位不支持时，按当前模型提供的档位重新选择。

发送前确认模型选择器对应的是你要点名的伙伴。运行中换模在后续模型请求边界生效，不会改写已完成的回答。

## 把伙伴加入任务

在任务的「伙伴」面板添加需要的成员。普通输入发给当前主角；输入 `@` 并从候选项选择一位已加入的伙伴，可以把本次要求交给它，而不更换当前主角。只在正文里输入名字不是点名；多点名时仍由当前主角接收并协调。

切换主角后，下一轮普通输入由新主角接手。已经开始的执行仍属于原来的伙伴，不会因为切换选择器而换人。

可以先从两位伙伴开始：一位写初稿，一位提出修改意见。分工要具体，尤其在处理同一份文件时，说明谁负责修改、谁只给建议。

## 点名修改与继续已有工作

希望原作者修改时，单独点名它，并引用答案或注明产物与修改范围，例如“@小克 继续修改你刚才的开头，保留风铃的细节，更新同一份草稿”。正在工作时，补充或排队遵循[工作中发送策略](./ai-chat#运行时补充要求)。

不点名的修改要求仍由当前主角协调，不会自动交给最近发言的人。若要续做先前的某项工作，说清任务和产物，不要只说“继续”。交接已接收不等于修改已完成，仍要打开最终文件检查。

## 为主角招募 NPC

在伙伴配置的 NPC 小队中招募需要的角色。内置角色包括探索者、研究员、执行者与审查者；你也可以创建自己的 NPC，设置其行动准则、模型与能力。

NPC 适合范围清楚的子任务，例如“只核对这三个地点的来源，返回有疑问的条目”。主角收到结果后继续推进整体目标。

- NPC 不出现在普通 `@` 成员列表；由绑定它的伙伴调用，不能再派出下一层子任务。
- 新工作使用独立上下文，不会自动读到整段主对话；委派时需要交代材料、交付物与验收要求。续做应明确原工作。
- NPC 可以向你提问，过程可在执行详情查看；它的私有过程不会自动成为主对话正文。
- 小队开关、NPC 启用状态与能力选择都可能影响可用性。关闭小队不等于取消已经接受的工作。
- 多位伙伴可能操作同一目录，独立上下文不代表文件隔离；明确谁写文件、谁只审查。

## 为什么没有按预想协作

- **无法点名**：先确认伙伴已加入当前任务，而不仅仅存在于管理页。
- **不能调用 NPC**：检查小队开关、NPC 启用状态和与发起伙伴的绑定。
- **工具或 Skill 不可用**：检查连接或安装状态，以及伙伴的能力选择。
- **换了默认伙伴，旧任务没变**：默认伙伴影响新任务；旧任务的当前主角需要单独切换。

每位伙伴的请求都可能消耗模型额度。先用清楚的小分工验证效果，再扩大协作范围。模型设置见[连接模型](./settings-and-models)，权限设置见[执行权限](./permissions)。
