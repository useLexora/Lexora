# Spec-001：AI 回答过程总折叠方案

**日期：** 2026-09-27
**状态：** 已审核通过；已实现

## 1. 背景

目前对话回答中的思考、工具调用及其他过程内容分别呈现，缺少一个覆盖整段回答过程的总折叠入口。过程内容较多时，会挤占最终回答的可见空间；单段折叠不能满足“只保留最终回答和必要内容”的阅读需求。

参考项目 `D:\code\zcode XTLAW\deepseek-harness` 的实现，按一次完整回答（Turn）界定过程范围，用一个 Turn 级控制器统一折叠回答前的过程，并让最终回答保持可见。本方案只描述目标行为，不要求照搬参考项目的架构或代码。

## 2. 目标与核心规则

**目标：** 一次完整回答中，最终回答前的思考、工具调用和过程消息由同一个总折叠控制；最终回答不随过程一起隐藏。

**核心规则：**

1. 每个完整回答独立划定过程范围，范围从该回答开始产生过程内容处开始，到最终回答开始处结束。
2. 折叠时，统一隐藏该范围内的过程内容，包括多段思考、多个工具调用、工具结果及其他属于过程的消息。
3. 最终回答始终单独显示，不纳入过程折叠范围。
4. 用户可通过总折叠入口展开或收起整段过程；逐条思考或调用的局部展开能力可保留，但不得替代总折叠。
5. 不同回答的折叠状态彼此独立；收起或展开一个回答，不影响其他回答。

## 3. 场景与预期行为

### 3.1 正常完成

- AI 正在生成时，过程内容可按现有交互展示；运行中的回答不应被总折叠意外隐藏。
- AI 生成最终回答并正常结束后，过程整体默认收起；最终回答完整可见。
- 总折叠入口位于顶部头像区域右侧，显示回答状态和耗时；不在过程区重复显示入口。
- 用户展开后可查看该回答的全部过程；再次收起后最终回答仍留在原位置并保持可见。

### 3.2 只有思考、只有调用或多段过程

- 即使只有一段思考或一次调用，也应服从同一个总折叠，不因内容“只有一项”而绕过总入口并默认铺开。
- 多段思考与多个工具调用必须由同一个入口整体控制，不要求用户逐段收起。
- 过程内容为空时，不显示无意义的折叠入口。

### 3.3 中断与失败

- 仍在运行中的回答保持可观察，不应按已完成回答的默认策略自动收起。
- 中断或失败的回答默认保留过程展开状态，以便查看诊断信息；失败详情独立显示，不因过程收起而消失。

### 3.4 特殊消息边界

- 用户消息、回答前后独立的系统提示/状态提示、审批控件等，不应仅因时间上邻近回答过程而被误收起。
- 多轮工具调用、模型继续生成以及最终回答边界应按同一回答归组，不能把下一次回答的内容误并入前一组。
- 若一次运行产生多个 assistant 回合/中间回复，需依据当前运行数据确定哪些节点属于“过程”，并确保最终面向用户的回答保留显示。

## 4. 需求边界

**包含：**

- 对话转录区中的回答级过程分组与总折叠交互。
- 折叠范围覆盖回答前的思考、工具调用及对应过程内容。
- 最终回答独立呈现且在折叠状态下可见。
- 运行中、完成、中断、失败等状态对应的折叠策略。
- 键盘操作、无障碍状态（例如展开按钮的 `aria-expanded`）与折叠状态测试。

**不包含：**

- 修改模型推理、工具执行、流式协议或对话持久化格式，除非实现阶段证明这是划分边界所必需的；如需变更，应另行说明并审阅。
- 删除现有逐条思考/工具细节展开能力。
- 改造独立的对话画布、运行日志、调试轨迹等非聊天转录视图。
- 直接复制参考项目的数据结构、状态管理或组件实现。

## 5. 交互与界面示意

以下示意为已确认并已实现的 UI 结构。顶部头像区域保持透明，头像、名称、状态、耗时和箭头属于同一个整条点击区域；分隔线位于该区域下方，用来区分过程区与最终回答。

### 5.1 思考进行中

```text
[头像] Lexora Buddy                         运行中  >
────────────────────────────────────────────
思考内容……
工具调用……
工具结果……
```

- 顶部头像条显示运行状态；运行期间箭头不可操作。
- 运行期间过程可见；思考与工具调用都属于同一过程区。
- 头像条底部显示浅色细分隔线，与后续过程/最终回答区域分开。

### 5.2 最终回答完成，过程默认收起

```text
[头像] Lexora Buddy                         已完成 18 秒  >
────────────────────────────────────────────
最终回答正文……
```

- 顶部头像条显示完成状态和耗时；整条区域点击可展开过程。
- 思考、工具调用及其结果整体收起，不逐段散落在最终回答之前。
- 分隔线保留，最终回答始终完整显示在其下方。

### 5.3 最终回答完成，过程展开

```text
[头像] Lexora Buddy                         已完成 18 秒  <
────────────────────────────────────────────
思考内容……
工具调用……
工具结果……

最终回答正文……
```

- 点击顶部头像条展开回答前的完整过程；再次点击后整体收起。
- 展开/收起只影响过程内容，不隐藏或折叠最终回答。

### 5.4 交互规则

- 折叠入口放在顶部头像条；点击区域从头像开始延伸到最右侧箭头，顶部透明，底部细分隔线作为过程区与回答区的视觉边界。
- 默认策略：运行中过程保持可见；正常完成后过程默认收起；历史记录首次加载时也按完成态收起。
- 用户手动展开/收起后，在本次页面会话内尊重其选择；是否跨会话/重启持久化不在当前默认范围内。
- 摘要只显示回答状态和耗时，不显示思考全文或调用数量。
- 审批卡、思考、工具调用、工具结果、旁白和面板操作属于过程区；失败详情独立保留并始终可见。

## 6. 实现方向与结果

参考项目将过程归属提升到回答/Turn 级：先计算过程节点和最终回答边界，再用统一的回答级状态控制过程节点可见性，同时让最终回答独立呈现。本项目在展示层完成了同等交互，不改动模型事件协议或持久化结构。

实现时已验证：

1. 现有 `turn.nodes` 经过活动投影后作为统一过程区渲染，最终回答仍独立显示。
2. 运行中强制保持过程可见，完成态默认收起，失败/中断保留过程可见性。
3. 活动分组、叙述文本、面板操作和审批提示归入总折叠；失败详情独立保留。
4. 折叠状态由每个 `BuddyChatAgentTurn` 独立维护，不影响相邻回答。

不得仅将现有 `BuddyChatActivityGroup.vue` 的每组折叠逻辑当作总折叠；总控制必须覆盖整个回答过程范围。

## 7. 验收标准

- [x] 正常完成且包含多段思考和多个工具调用时，默认仅显示顶部总过程入口与最终回答；过程细节整体收起。
- [x] 展开顶部总入口后，可看到该回答范围内所有思考、调用及相关过程节点。
- [x] 收起顶部总入口后，所有上述过程节点均隐藏，最终回答仍完整可见。
- [x] 只有一段思考、只有一次工具调用、无思考只有调用、无调用只有思考等情况均服从同一总折叠规则。
- [x] 正在运行时按明确的运行态策略展示，不因节点数量或分组方式而绕过预期行为。
- [x] 一个回答的展开状态不会错误影响相邻回答；前一回答折叠不会隐藏后一回答的最终回答。
- [x] 中断、失败、审批等待及重试场景均有可理解且可操作的展示，不丢失错误/审批信息。
- [x] 键盘可操作总折叠入口；展开状态通过无障碍属性正确暴露。
- [x] 已覆盖完成态默认折叠、运行态转换、多段活动归组和最终回答常显的自动化测试。

## 8. 已确认的设计决策

1. **最终回答边界：** 继续沿用当前 `ChatAgentTurn` 的节点投影，最终回答独立显示，不纳入过程内容的隐藏范围。
2. **运行时策略：** 运行中保持过程可见；正常完成后默认收起。
3. **失败/中断默认状态：** 默认保留过程展开状态；失败详情独立显示，方便诊断。
4. **折叠状态记忆：** 仅在当前组件/页面生命周期内保留用户选择，不跨会话持久化。
5. **摘要内容：** 顶部头像条显示回答状态和耗时；不显示思考段数、调用数量或思考全文。
6. **特殊节点归属：** 审批卡、面板操作、过程旁白、思考、工具调用及工具结果纳入总折叠；失败详情保持独立可见。

## 10. 审阅结论

**审核结论：已通过（2026-09-27）**

- 采用“正常完成后默认收起、运行中保持可见、最终回答始终显示”的默认策略。
- 顶部头像到箭头的透明长条为总折叠点击区域，箭头位于右侧状态文字之后。
- 失败/中断过程默认保留可见性；审批卡等过程节点随总折叠控制，失败详情保持独立可见。
- 折叠选择只在当前页面生命周期内有效，不做跨会话持久化。
